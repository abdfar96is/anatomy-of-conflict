# M2 Map + Shell Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The React app shows today's map with every lens, layer, legend and map control, inside today's app chrome:
- the top bar and lens rail
- the command palette, help dialog and toasts
- the phone menu and the global keyboard map

The result must work in Arabic and English, dark and light, on desktop and on a 390 px phone. Dossiers, views, the scrubber and tours remain placeholders until M3.

**Architecture:**
- **Map (spec D2):** the canvas engine stays imperative. `legacy/js/map.js`, `map-geo.js` and `map-scene.js` are ported to TypeScript nearly line by line. They read state with `atlas.get()` and react to changes through `onStateChange` (the legacy `on('change', {keys})` contract, now derived from the Zustand store).
- **Chrome:** the legend, map controls and shell are rewritten as React components with the same DOM ids, class names and CSS, so today's stylesheets apply unchanged.
- **Shared code:** UI helpers (`src/ui/*`) and the palette are ported once (Task 1) and used by both sides.

**Tech Stack:** as M1, plus `d3` 7.9.0 (the full package, replacing `d3-geo`). Legacy code uses zoom, interpolate, scales, colour and force from it, and `import * as d3 from 'd3'` keeps the port close to the original while Rollup tree-shakes the static member accesses.

**Spec:** `docs/superpowers/specs/2026-10-31-react-open-source-design.md`. Prior milestone: `docs/superpowers/plans/2026-10-31-m1-handoff.md` and its ledger.

## Global Constraints

- **Look and feel are unchanged:** same DOM ids and classes as `legacy/index.html` and `legacy/js/*`, and the CSS files are copied from `legacy/css/*`. No visual redesign (D3).
- **Language and theme:** Arabic RTL is the default; English is LTR. Dark and light themes both work.
- **Phone:** no sideways scroll at 390 px.
- **Text safety:**
  - Strings that end up in `innerHTML` (map tooltips, the engine, `data-tip`) go through `esc()`.
  - React components render text as children, never with `dangerouslySetInnerHTML`, except for the trusted `icon()` SVG strings and the legacy `data-tip` HTML built with `esc()`.
- **Module boundaries:** features don't import each other. They talk through `useAtlas`/`atlas` (`src/app/store.ts`), `onStateChange` (`src/app/compat.ts`) and `events.ts`.
- **Strings:** each feature registers its own strings with `registerStrings` (copied from the legacy module) and reads them with `useT().t`.
- **Commits:** one per task, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Never push.
- **Every task ends with** `npx vitest run`, `npx tsc --noEmit` and `npx eslint .` all green.

## Review Focus

1. **Theme switch while the map is shown:** canvas colours must follow (palette cache reset). Covered by a Task 1 test plus a browser check.
2. **Switching language flips the layout:** the map labels, legend and rail mirror without a reload. Covered by the browser check.
3. **Resizing to phone width and back:** the canvas resizes, and the DPR stays capped at 2. Covered by the browser check.
4. **Esc order** (palette → help → popover/menu → tour → view → selection): one level per press. Covered by a Task 3 test.
5. **Keyboard shortcuts while typing in an input:** they must not fire. Covered by a Task 3 test.

### Task 1: Shared UI, palette, state-change bridge, layout skeleton (lead)

**Files:**
- Create:
  - `src/ui/dom.ts`: `esc`, `icon`, `h`, `$`, `$$`, `cssVar`, `copyText`, `shareLink`, `reducedMotion`, ported from `legacy/js/ui.js`
  - `src/ui/tooltip.ts`: `showTip(html, x, y)`, `hideTip()`, `initTips(): () => void`
  - `src/ui/Icon.tsx`: `<Icon name size? />`
  - `src/ui/palette.ts`: `catVar`, `sevVar`, `edgeVar`, `familyVar`, `resClassVar`, `isDark`, `pal`, `traditionColor`; the cache resets on a theme change or an OS scheme change
  - `src/app/compat.ts`: `onStateChange(fn: (keys: (keyof AtlasState)[], s: AtlasState) => void): () => void`, which lists the top-level keys whose reference changed
  - `src/features/layout/Layout.tsx`: today's skeleton, with `#app` > `#topbar`, `#lensrail`, `#stage` > (`#map`, `#viewpanel` hidden), `#scrubber`, `#dossier` hidden; then `#tooltip`, `#palette`, `#help`, `#tour`, `#ask` hidden, and `#toasts`
  - `src/styles/{shell,map,dossier,views}.css`, copied from `legacy/css/`
- Modify: `src/App.tsx` (render `<Layout/>`), `src/main.tsx` (import the CSS)
- Test: `tests/ui.test.ts`

The tests cover:
- `esc('<a href="x">')` returns `'&lt;a href=&quot;x&quot;&gt;'`.
- `icon('globe')` contains `<svg class="ic"` and the globe path.
- `catVar(3)` returns `'var(--cat-3)'`, and `edgeVar('alliance')` returns `'var(--cat-3)'`.
- `onStateChange` reports `['lens']` after `atlas.set({lens:'religion'})`, and `['filters']` after `atlas.toggleInSet('severity','war')`.
- After `initTips()`, a `pointerover` on `<b data-tip="hi">` shows `#tooltip` with `hi`.
- `pal()` returns a new object after `atlas.set({theme:'light'})`.

**Files:**
- Create:
  - `src/features/map/engine/geo.ts` (port of `map-geo.js`)
  - `src/features/map/engine/scene.ts` (port of `map-scene.js`)
  - `src/features/map/engine/engine.ts` (port of `map.js`)

- Test: `tests/map-scene.test.ts`, `tests/legend.test.tsx`

**Interfaces:**
- `createMap(mount: HTMLElement, db: DB): MapApi`.
- `MapApi` exposes what `map-legend.js` `mountControls(stage, api)` uses today (zoom in and out, reset, projection), plus `destroy()`.
- The engine handles `flyto` and `highlight` from `events.ts`, and emits `hover`.
- `AtlasMap` creates the engine once on mount and destroys it on unmount (StrictMode safe).

The tests cover:
- `buildScene(db, state, pal)` for `overview`, `conflicts`, `religion` and `powers` returns non-empty fills, and the markers and arcs today's code produces. Check the counts against a run of the legacy functions on the same data. The repo has a Node harness pattern at `tests/helpers/readRaw.ts`.
- `tipFor` for a country hit includes the escaped country name.
- Legend: clicking a mode chip on the religion lens sets `filters.religionMode`. The legend title follows the lens in both languages.

### Task 3: Shell (implementer B)

**Files:**
- Create, under `src/features/shell/`:
  - `TopBar.tsx`, `LensRail.tsx`, `CommandPalette.tsx`, `HelpDialog.tsx`, `ToursMenu.tsx` (a button and popover listing `availableTours`; the player is M3), `PhoneMenu.tsx`, `Toasts.tsx`
  - `keyboard.ts` (the global key map and Esc order)
- Modify: `src/features/layout/Layout.tsx`, to mount them in their legacy containers
- Test: `tests/shell.test.tsx`

This is a React rewrite of `legacy/js/shell.js`. Keep its strings, keys and behaviour. `markMatch` is ported as a pure function. Tour metadata comes from `legacy/js/tours.js`: port only `TOURS`, `availableTours` and `stepsLabel` into `src/features/tours/tours.ts`.

The tests cover:
- Clicking a lens in the rail sets `lens`.
- `/` opens the palette.
- Typing `السعوديه` lists Saudi Arabia first, and Enter selects `country:SAU`.
- With the palette open and a selection set, Esc closes the palette but keeps the selection; a second Esc clears the selection.
- `/` typed inside an `<input>` does not open the palette.
- The language button switches `lang`, and the theme button cycles system → dark → light.
